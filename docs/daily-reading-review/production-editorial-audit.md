# 일일 해설 실제 응답 점검 — 2026-11-04

## 확인 범위

사용자가 첨부한 2026-11-04 화면과 일치하는 저장된 Gemini 응답, 생성 이력, 같은 날짜 계산 자료를 읽어 비교했다. 초기 점검은 읽기 전용으로 수행했다. 이후 별도 QA 함수와 QA 전용 가상 프로필로 실제 Gemini 생성 검증을 추가했다. 운영 함수·웹앱은 교체하지 않았다. 개인정보가 포함된 원본은 저장소에 포함하지 않았다.

원래 전송 프롬프트는 보관되어 있지 않다. 보관된 계산 자료로 입력을 재구성했지만 해시가 기존 작업과 달라, 원래 요청을 바이트 단위로 복원했다는 주장은 할 수 없다. 아래 검사 재현은 이 재구성 입력을 사용한다.

## 수정

- 일일 기본 6분야를 명시적으로 요구한다. 실제로 해석할 근거가 없으면 해당 상태를 명시하며 전체 요약으로 빈 분야를 채우지 않는다.
- 분야별 질문·전달 근거·시간창 범위를 프롬프트에 연결한다. 근거가 있다는 사실을 사건 예측의 타당성으로 취급하지 않는다.
- 지원·주의 방향이 확인되지 않은 총평은 `context_only`로 구분한다. 없는 대비와 우선순위를 만들도록 강제하지 않는다. 높은 활성도만으로 지원 방향이라고 판정하지 않는다.
- 알려진 문장·시간창·분야 모순·Thai 근거 과장 사례를 일일 전용 검사에 추가한다. 기존 6단계의 마지막 단계에 실패 사유를 연결하고 최대 2회 호출 안에서 Gemini 재작성을 요청한다.
- V23에서는 시각 없는 행동도 허용한다. 시각을 쓴 경우의 근거 검사는 유지하며, 이전 버전의 기본 정책은 유지한다.
- 자동 근거 보강 전 Gemini가 작성한 근거 연결을 먼저 검사한다. 서버가 문장을 대신 써서 통과시키지 않는다.

## 검증과 남은 일

- 별도 코드 검토에서 시각 생략 우회·한국어 시각 표기·제한 설명 오탐·면책 문구에 의한 우회·시간대 강제 충돌을 확인하고 수정했다.
- 관련 백엔드 테스트 131개 통과, 신규 검사 모듈 TypeScript 검사 통과, 웹 앱 빌드 통과. 기존 큰 번들 경고는 남는다.
- 새 검사는 알려진 실패 사례를 잡는 제한된 규칙이다. 모든 문장의 자연스러움이나 해석 타당성을 보증하지 않는다.
- 기존 GitHub Actions의 QA 로그인과 서버 Gemini 연결을 확인했다. 로컬 키 없이 실행 가능한 인증 경로가 있으며, 사용자의 추가 로그인이나 직접 테스트는 필요하지 않았다.
- 실제 QA r1은 실패, r2·r3는 자동검사를 통과했으나 원고 검수에서 보류, r4~r6은 재작성 또는 날짜 표현 검증에서 실패했다. r7은 Gemini 3.7 원고의 날짜 표현 두 곳만 Gemini 3.6이 수정한 뒤 전체 검사를 통과했다.

**원고 품질 때문에 운영 배포 보류. 사용자에게 직접 검증을 맡기지 않는다.**

- 사례 A: 01babb13-4d2c-4703-86eb-1dbc92fe4e32. 첫 원고 Gemini 3.7, 실패 문장만 Gemini 3.6이 수정.
